## Why

`fly` 当前只是一个空的 fuickjs 演示项目（仅有 Welcome 首页）。我们希望把它做成一个可玩的**宇宙进化游戏**：玩家扮演一颗陨石，在星空中通过操作杆移动，吞噬比自己小的天体、躲避比自己大的天体，按阶段收集物质并进化，最终成长为黑洞并跃迁到另一个宇宙。这能验证 fuickjs 框架承载实时交互游戏（游戏循环 + 高频重渲染 + 虚拟摇杆 + 拖拽捕获）的能力，同时交付一个完整的产品化示例。

## What Changes

- 新增游戏核心：实体模型（玩家、各类天体、被捕获的卫星）、游戏循环（基于 Timer/动画帧驱动）、移动与碰撞检测与结算规则。
- 新增进化系统：11 个等级（陨石 → 小行星 → 矮星 → 岩石行星 → 气态行星 → 矮恒星 → 恒星 → 巨星 → 超巨星 → 中子星 → 黑洞），以及每个等级所需的物质阈值与对应的吞噬 / 躲避 / 撞击 / 捕获规则。
- 新增操控：左下角虚拟摇杆控制玩家移动；到达岩石行星后可使用的右下角「捕获」按钮，捕获靠近的行星绕自身旋转以抵挡伤害。
- 新增渲染：用 fuickjs 的 `Stack` + `Positioned` 将星空调为多层绝对定位实体（玩家、自由天体、被捕获轨道天体），每帧由 JS 重渲染产出 DSL 交给 Flutter 绘制；轨道天体以环绕动画呈现。
- 新增 HUD 与结局：顶部显示当前等级、物质数量与升级进度条；被更大天体撞击扣血 / 游戏结束；达到黑洞且累计 5000 物质后进入「另一个宇宙」结局画面。
- 占位首页（`pages/home.tsx`）改造为游戏入口，启动游戏页面。

## Capabilities

### New Capabilities
- `cosmic-evolution/game-core`：实体数据模型、游戏循环驱动、移动与碰撞检测 / 结算（吞噬、撞击、受伤）的核心机制。
- `cosmic-evolution/evolution`：11 个进化等级的等级定义、各等级物质阈值、以及每个等级允许的吞噬 / 躲避 / 撞击 / 捕获行为规则。
- `cosmic-evolution/controls`：左下角虚拟摇杆（方向 / 力度输入）与右下角捕获按钮的交互与输入处理。
- `cosmic-evolution/rendering`：星空调度渲染——`Stack`/`Positioned` 实体布局、轨道环绕动画、被捕获天体的视觉表现。
- `cosmic-evolution/hud`：等级 / 物质 / 进度 HUD、受伤与游戏结束、5000 物质后的「另一个宇宙」结局界面。

## Impact

- **代码**：新增 `js/src/game/`（核心、进化、实体、循环）、`js/src/components/`（摇杆、捕获按钮、HUD、星体）、`js/src/pages/game.tsx`（游戏页），改造 `js/src/pages/home.tsx` 作为入口，`js/src/store` 增加游戏状态。
- **框架依赖**：仅使用 fuickjs **现有导出能力**（已确认具备 `GestureDetector.onPanUpdate`、`Stack`、`Positioned`/`AnimatedPositioned`、`Container`、`CustomPaint`、`Timer` 服务等），**不修改框架层**。
- **性能**：每帧全量重渲染 DSL 给 Flutter，需控制实体数量与重渲染频率（如 30fps）以保性能——此为设计阶段需评估的关键风险。

## 已与用户确认的假设

- **等级命名对齐**：用户口中的「矮行星」（L2 小行星需躲避者）即等于 **矮星(L3)**，并非独立等级或障碍类型。由此各等级规则统一为「需躲避比自身高一级的天体」（小行星躲矮星、矮星躲岩石行星……）。
- **渲染方式**：采用 `Stack` + `Positioned` 绝对定位逐帧重渲染（兼容现有原语），不在框架层新增 Canvas。
- **实现边界**：仅修改 `fly` 业务层，不改动 `fuickjs_framework` 框架层（不新增/修改 Widget 或服务，故无需同步框架文档）。
- **受伤模型**：采用**血条**——被比自身大的天体撞击扣血，生命归零则游戏结束；被捕获的轨道天体会优先替玩家抵挡伤害并碎裂。
- **坐标与碰撞**：使用简单的圆形碰撞（半径基于天体等级/尺寸），在 JS 内计算。
